# AI-ATC Vision

## High-Level Goals

Build a fully offline, local-first **Artificial Intelligence Air Traffic Control (AI-ATC)** system that integrates with Microsoft Flight Simulator (MSFS) via SimConnect. The system replaces or augments default MSFS ATC with intelligent, context-aware, natural-language radio communications driven by local LLMs and speech pipelines.

### Tenets

1. **Offline & Local-First** — Everything runs on consumer hardware with no cloud dependency. STT (Whisper.cpp), LLM (Ollama), and TTS (Piper) all execute locally.
2. **Deterministic + Non-Deterministic Separation** — Flight dynamics, navigation, and controller state machines are deterministic (Python/C#). Speech, dialogue generation, and pilot intent parsing are non-deterministic (LLM). The two domains communicate only through well-defined interface boundaries.
3. **Modular Monorepo** — Each service has a single responsibility. Services communicate over gRPC or WebSocket with typed schemas. No shared mutable state.
4. **Real-Time First** — Audio streaming, telemetry, and radio events target sub-200ms latency. The speech pipeline (STT -> LLM -> TTS) is pipelined for streaming partial results.
5. **Safety-Conscious Design** — The deterministic controller layer must never depend on LLM output for safety-critical decisions. ATC clearances generated by the LLM are validated against the current controller state machine before transmission.
6. **Open Standards** — OpenAPI, JSON Schema, Protocol Buffers, Mermaid diagrams. All interfaces are documented before implementation.

## Philosophy

AI-ATC treats the pilot as a user of a real-world ATC system. Radio calls follow FAA/ICAO phraseology. The LLM acts as a "controller assistant" that generates natural-language responses under the supervision of deterministic state machines. This hybrid approach ensures that while the AI can handle unexpected phrasing or non-standard calls, it can never issue a clearance that violates separation minima or airspace rules.

## Design Principles

| Principle | Description |
|-----------|-------------|
| **Interface First** | All cross-service contracts are defined and versioned before any implementation. |
| **Fail Closed** | If the LLM is unavailable or produces invalid output, the controller falls back to silent mode (no transmission) rather than generating garbled instructions. |
| **Observability** | Every service exports structured logs and Prometheus metrics. Audio pipeline emits per-chunk latency histograms. |
| **Reproducibility** | Entire environment is Docker Compose with pinned versions for all ML models and system dependencies. |
| **Progressive Enhancement** | Core ATC functions (ground, tower, approach) work without LLM. Speech and dialogue are additive layers. |
